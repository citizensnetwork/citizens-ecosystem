## What was found while writing them

1. **Follow already has its tables, and Events already have a bookmark.** `follows` (a Contributor is a profile) and `place_follows` exist; an Event has both **Connect** and **Consider**, two states of one `rsvps` row. So Save is a **private** second concept next to a public Follow: Stephen chose to have it (his answer of 2026-10-17), and the sheet now offers both.
2. **Follower notifications reuse the existing switch.** `contributor_updates` ("Broadcasts and updates") is already in Settings and already on by default; the new trigger reads it, so there is no new setting.
3. **The `follows` privacy gap is wider than the table.** `follows` and `place_follows` are readable by the public key (verified 2026-10-15 and again 2026-10-17: the `SELECT` policy is `true` and `anon` holds `SELECT`), and **two public APIs also return exact follower counts** (`/api/contributors/search` and `/api/v1/contributors/<slug>`), so the "never show a low number" rule (P2-08) was a display rule only. Every reader of both tables was audited (browser, API routes, Edge Functions, SQL functions, Vision, Wear): the full table is in `s13-follows-privacy.md`. Four readers would break if the table were closed without a change (the contributor API, the dashboard count, the messaging rule, the broadcast recipients), plus `search_contributors` and `count_friends`; the three SQL files and four code edits keep every one of them working.
4. **Fixed without a migration (2026-10-17):** every Contributor and Place card and profile page printed **"0 followers"** (a real listing carries no count, so it was always the default). They now show the bucket from 100 or nothing. A signed-out visitor who tapped Follow got a heart that was gone on refresh; they are now asked to sign in.

## Still open

1. **Convince cannot pass for most people (found 2026-10-18, not caused by S13): RESOLVED the same day by migration 190.** The policy "Mutual friends can send convinces" checked that the other person was `considering` the event by reading THEIR `rsvps` row, and `rsvps` is readable only by its owner and the event's organiser, so only an organiser could pass it. The audit of the whole path found five more holes (a block was ignored, cancelled and ended events accepted a nudge, withdraw-and-resend notified again, `anon` held all privileges on the table, `is_mutual_follow` had the loose search path); [`convince-fix.sql`](./convince-fix.sql) closed all six (applied as `supabase/migrations/190_convince_fix.sql`; probe 34 of 34 in `docs/audit/probes/190_convince_fix.probe.sql`). **The entry point is built** (draft PR #151, `claude/convince-ui`, after the founder ruled that "considering" is shown to mutual friends by default with an off switch): its SQL was applied as `supabase/migrations/191_friends_considering.sql` (see below). The screens ship when that PR is merged.
2. **A third public place that prints the exact follower number**: `GET /api/v1/contributors/<slug>/stats` (the `get_contributor_public_stats` function). Bucket it in a later migration, like 185 and 186.
3. **A user-facing Report button** does not exist for any content (the database and the API accept a report about an event, user, place, comment, conversation or moment, and the admin list shows them). Moments are reportable only through the API today.
4. **`invite_event_cohost` has no per-inviter daily cap**; and a saved listing that is no longer on the map shows only as a count in Settings.
